# Contrôles du lot justificatifs — 5 novembre 2026

## Vérifications réellement réalisées sur Linux

- **Android : 112 tests JVM ciblés réussis sur 13 classes**, aucun ignoré ni échec, après compilation de la version beta.29. Ils couvrent notamment limites, stockage Room, rejet de conflit, rollback, Undo de dépense, interface Compose et sélection de photo simulée. Dans cette simulation, une image fictive contenant des coordonnées EXIF est choisie, réencodée, enregistrée et relue sans ces coordonnées ; un fichier invalide laisse l’ancienne photo inchangée. Des messages du décodeur simulé Robolectric « unimplemented » sont apparus sans échec. Cela ne valide ni une galerie réelle ni les performances d’un téléphone.
- **PWA : 47 tests unitaires réussis.** Les parcours de justificatifs et de dépenses réussissent sous Chromium et WebKit Linux : ajout, aperçu, remplacement, retrait, annulation, panne de quota simulée, photo illisible préservée, conflit entre deux onglets et réutilisation hors ligne après mise en cache. Fermeture bloquée pendant une lecture/écriture volontairement ralentie.
- **Pont fictif complet Room → PWA → Room → PWA** exécuté séparément avec Chromium et WebKit Linux. Il comporte une image JPEG fictive d’environ 1,05 Mio avec métadonnées GPS fictives et plusieurs blocs Room de 128 Kio, un nombre d’extension préservé exactement, une enveloppe de version future, modification, suppression/Undo, sauvegarde et aperçu. Le retour Chromium est inclus comme fixture synthétique dans les sources : ce ne sont pas des données personnelles.
- Mises à jour **PWA 1.5.1 → beta.4** et **beta.3 → beta.4**, même origine et données fictives, vérifiées sous Chromium et WebKit Linux ; nouvelle mise en cache et fonctionnement hors ligne vérifiés dans ces scénarios. WebKit Linux n’est pas Safari sur iPhone.
- Les **15 schémas Room**, le manifeste Android et les règles d’extraction ont été comparés à beta.28 : identiques. JSON v3, Room 15 et IndexedDB 4 inchangés.
- APK **debug** assemblé : `com.vigieauto.app`, version code 33, min 26, cible 36, **12 450 081 octets**. SHA-256 `c9330809aa6fc7a1de8314997d306dc46ce09fc2fd90a408e702b99a64458059`. Seule permission déclarée : permission interne du récepteur. Ce fichier debug est un contrôle local, non inclus dans le ZIP source ; ce n’est pas une release signée ni une mesure de taille de distribution.
- Lint debug : **0 erreur, 20 avertissements, 3 indications** ; une indication concerne un état Compose pouvant être spécialisé. **61 scénarios instrumentés compilés mais non exécutés.** Aucun émulateur ni téléphone n’a été utilisé.
- Tests synthétiques des scripts : archiveur Android **23/23**, archiveur PWA **17/17**, vérificateur de rapports CI **25/25**, workflow **7/7**, vérificateur R8 **22/22**. Le vérificateur CI a été testé sur données synthétiques ; la porte globale n’a pas été exécutée sur une suite complète beta.29.

## À ne pas conclure

La **suite JVM complète n’a pas été relancée pour beta.29** ; le dernier passage complet documenté est celui de beta.28. Pas d’essai de cette version sur Windows, CI GitHub, émulateur, téléphone Android ou Safari iOS. Les scénarios Linux et les fixtures sont fictifs. Les temps de démarrage, fluidité, FPS, mémoire, batterie, import/export et taille d’une release n’ont pas été mesurés sur appareil : les objectifs restent ouverts.

Avant tout essai avec vos données, exporter et vérifier une **copie externe** de chaque appareil. L’import confirmé remplace le carnet destinataire et ne fusionne pas les données. Fermer les anciens onglets PWA avant l’essai, car certaines anciennes versions ne détectent pas les conflits. Les sauvegardes et photos ne sont pas chiffrées par VigieAuto ; les photos originales de la PWA et les photos importées sur Android peuvent garder des métadonnées GPS. Voir [JUSTIFICATIFS-BETA29.md](JUSTIFICATIFS-BETA29.md).
